Fine-tune your documentation site's visual appearance by customizing specific color elements and typography. This guide focuses on detailed color customization beyond basic theme setup to achieve perfect brand alignment.

These site-wide color settings work together with [page-level front matter](page-configuration) to create a cohesive brand experience across all documentation pages.

## Prerequisites

- Basic understanding of theme and color setup

- Your brand color palette or style guide

- Access to your `documentation.json` file

- Understanding of hex color codes and contrast ratios

## Customize Colors from the Editor (recommended)

You can configure your brand, heading, and text colors directly from Site Config in the Editor without editing JSON.

### Step 1: Open Theme Colors

1. In the Editor, click **Site Config** in the top toolbar.

2. Scroll down to the **Theme Colors** section.

All changes made here are stored under `colors` in `documentation.json` and appear in the **Changes** panel. Publish your documentation to apply the changes.

### Step 2: Configure Light and Dark Theme Colors

In the **Theme Colors** section you’ll see two columns: **Light Theme** and **Dark Theme**. Each column lets you configure the same set of properties:

- **Brand**\
  Sets your primary brand color for interactive elements such as call-to-action buttons, links, and selections.

- **Heading**\
  Defines the color used for headings and titles across your documentation.

- **Text**\
  Controls the main body text color for optimal readability.

**Recommended usage:**

- **Light Theme**

  - Choose colors that work well on light backgrounds.

  - Ensure body text and headings have sufficient contrast against the page background.

- **Dark Theme**

  - Use a lighter/brighter version of your brand color for interactive elements.

  - Pick heading and text colors with high contrast on dark backgrounds to maintain readability and avoid eye strain.

<Callout kind="info" collapsed="false">
  Use valid hex color codes (for example, `#1a1a1a`) and check that your combinations meet accessibility contrast requirements.
</Callout>

### Step 3: Apply Changes

1. Review your selections for both **light theme** and **dark theme.**

2. Save your changes if prompted.

3. **Publish** your documentation so the updated colors appear on your live site.

If you need more granular or automated control, you can also configure these colors directly in `documentation.json` as described below.

## Customize Brand Colors via Configuration File (Advanced)

Follow these steps if you prefer to manage colors through version-controlled configuration.

### Step 1: Identify your color requirements

Gather your brand colors in hex format:

- Primary brand color (for buttons, links, calls to action)

- Text hierarchy colors (headings vs body text)

- Ensure colors work for both light and dark backgrounds

### Step 2: Configure light theme colors

In your `documentation.json`, customize the light theme colors:

```json
{
  "colors": {
    "light": {
      "brand": "#3143e3",
      "heading": "#1a1a1a", 
      "text": "#374151"
    }
  }
}
```

**Configure each color property:**

<ParamField path="brand" param-type="string" required="false" deprecated="false">
  Set your primary brand color for interactive elements. Use hex format (e.g., `#3143e3`).
</ParamField>

<ParamField path="heading" param-type="string" required="false" deprecated="false">
  Choose a strong color for headings and titles. Default: `#1a1a1a`.
</ParamField>

<ParamField path="text" param-type="string" required="false" deprecated="false">
  Select a readable color for body text. Ensure good contrast. Default: `#374151`.
</ParamField>

### Step 3: Configure dark theme colors

Add complementary colors for dark mode that maintain brand consistency:

```json
{
  "colors": {
    "dark": {
      "brand": "#85a1ff",
      "heading": "#f2f2f2",
      "text": "#c1c1c1"
    }
  }
}
```

**Dark theme considerations:**

<ParamField path="brand" param-type="string" required="false" deprecated="false">
  Use a lighter/brighter version of your brand color. Use hex format (e.g., `#85a1ff`).
</ParamField>

<ParamField path="heading" param-type="string" required="false" deprecated="false">
  Choose high contrast colors for readability in dark mode. Default: `#f2f2f2`.
</ParamField>

<ParamField path="text" param-type="string" required="false" deprecated="false">
  Ensure sufficient contrast against dark backgrounds. Default: `#c1c1c1`.
</ParamField>

### Step 4: Test color combinations

1. Save your configuration

2. Deploy or preview your changes

3. Test both light and dark modes

4. Check text readability in various lighting conditions

5. Verify brand colors maintain visual hierarchy

## Choose Fonts

Your site uses Inter for text and JetBrains Mono for code until you choose other fonts. You can choose fonts for three parts of your site:

- **Heading**: page titles and headings. Until you choose one, headings use the body font.

- **Body**: all other text, including the sidebar and the navbar. Default: Inter.

- **Code**: code blocks, inline code and keyboard keys. Default: JetBrains Mono.

Heading and Body choose from the same text fonts. Code has its own list of monospace fonts:

- **Heading and Body**: Inter, Roboto, Open Sans, Montserrat, Poppins, Source Sans 3, DM Sans, Playfair Display, Plus Jakarta Sans and Geist.

- **Code**: JetBrains Mono, Roboto Mono, Source Code Pro, Fira Code and Geist Mono.

### Choose fonts from the Editor

1. In the Editor, click **Site Config**, then **Brand & Theme**.

2. In the **Fonts** section, open the **Heading**, **Body** or **Code** list.

3. Click a font to choose it. To go back to the default, choose the first entry in the list.

4. **Publish** your documentation so the new fonts appear on your live site.

### Set fonts in documentation.json

Add a `fonts` object with any of the three slots. Each slot names one font from its list:

```json
{
  "fonts": {
    "heading": { "family": "Playfair Display" },
    "body": { "family": "Poppins" },
    "code": { "family": "Fira Code" }
  }
}
```

<ParamField path="heading.family" param-type="string" required="false" deprecated="false">
  Font for page titles and headings. When omitted, headings use the body font.
</ParamField>

<ParamField path="body.family" param-type="string" required="false" deprecated="false">
  Font for all other text, including the sidebar and the navbar. Default: `Inter`.
</ParamField>

<ParamField path="code.family" param-type="string" required="false" deprecated="false">
  Font for code blocks, inline code and keyboard keys. Default: `JetBrains Mono`.
</ParamField>

Write each name exactly as it is listed above, capital letters included: `Playfair Display`, not `playfair display`. A name that isn't on the list is ignored, and that part of your site keeps its default font. Remove a slot to go back to its default.

### How fonts load for readers

Documentation.AI serves your fonts from your documentation site's own domain, and the fonts load with each page.

<Callout kind="info" collapsed="false">
  Only the fonts listed above can be chosen here. To use another font, such as a licensed brand font, load it with [Custom CSS](custom-css).
</Callout>

## Color Best Practices

Consider these guidelines when choosing colors:

### Contrast Requirements

- Maintain WCAG AA compliance (4.5:1 contrast ratio minimum)

- Test colors with accessibility tools

- Ensure readability for users with visual impairments

### Brand Consistency

- Use your brand's primary color for interactive elements

- Maintain consistent color relationships between themes

- Consider your brand's tone (professional, friendly, technical)

### Visual Hierarchy

- Make headings distinctly different from body text

- Use your brand color strategically to guide user attention

- Ensure navigation elements stand out appropriately

## Verify Your Color Setup

1. **Visual check**: Compare with your brand guidelines

2. **Contrast test**: Use tools like WebAIM Contrast Checker

3. **User testing**: Get feedback on readability

4. **Cross-browser testing**: Ensure consistency across browsers

5. **Accessibility audit**: Test with screen readers and accessibility tools

## Troubleshooting Common Issues

- **Low contrast**: Darken light theme text or lighten dark theme text

- **Brand mismatch**: Adjust colors to better match your style guide

- **Poor readability**: Increase contrast between text and background colors
