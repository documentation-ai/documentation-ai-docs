## Overview

Use code blocks to show syntax-highlighted code with a built-in **copy** button. Use **code groups** when you want **tabs** (for example, "JavaScript," "Python," and "cURL") so readers can switch between multiple examples in one place.

Code blocks and groups are ideal for:

- Single code snippets with syntax highlighting and copy support

- Multi-language SDK examples in tabs (similar to [Tabs](/components/tabs))

- Before/after, request/response, or setup/usage comparisons

- Step-by-step walkthroughs when combined with [Steps](/components/steps)

At a high level:

- **Code blocks**: One snippet, one language.

- **Code groups**: Multiple snippets, each with its own language and tab.

You can create both from the **Web Editor** or by writing MDX/Markdown in the **Code Editor**. The underlying syntax is the same, so you can safely switch between editors.

## Using with Web Editor

In the Web Editor, use the slash menu to insert and manage code blocks and groups.

### Insert a code block

1. Place your cursor on a new line.

2. Type <kbd>/</kbd> and select **Code Block**.

3. An empty code block appears. Paste or type your code into it.

Hover over the block and use the language dropdown on the top-right to pick the correct language.

### Insert a code group

1. Place your cursor on a new line.

2. Type <kbd>/</kbd> and select **Code Group**.

3. A group is created with a default tab (for example, **Tab 1**) and a code editor area.

<Image src="https://blob-cdn.documentation.ai/org-53a37986-2c9e-4094-b9e8-1e1ffae9e9ee/doc-b389b141-ae58-4fd5-91f9-6702fae9ac58/1767254609053-kupzap94d3p-pasted-image-1767254606676.png?q=85&fm=auto&auto=compress%2Cformat" width="600" height="162" alt="Code Group in Web Editor" caption="Code Group in Web Editor" style="width: 600px; height: auto; cursor: pointer; margin: 0 auto;" />

Inside a code group you can:

- **Add a tab**: Click the **+** next to the last tab.

- **Rename a tab**: Double-click the tab label (for example, "Tab 1") and type a new name (for example, "TypeScript" or "Python").

- **Remove a tab**: Use the tab's close icon (if available) or delete the last remaining tab to remove the group.

- **Pick a language per tab**: Use the language dropdown on each tab's code block.

The group toolbar also lets you **duplicate** or **delete** the entire group.

### Code block controls

Hover over a code block, or edit it, to see the controls in its header. In the Code Editor, write the same options as attributes after the language.

| Control                 | What it does                                                                                    | Attribute                          |
| ----------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------- |
| Icon slot               | Draws an icon before the file name. Hover to see **Add an icon**.                               | `icon`                             |
| File name field         | Shows a file name or a short label above the code. The field shows the language until you type. | `title`                            |
| Language dropdown       | Sets the language for syntax highlighting.                                                      | The word after the backticks       |
| **Lines**               | Turns on **Line numbers**, and sets the lines to **Highlight** and **Focus**.                   | `show-lines`, `highlight`, `focus` |
| **Wrap long lines**     | Wraps long lines instead of scrolling sideways.                                                 | `wrap`                             |
| **Code block settings** | Turns on **Expandable**, or turns off the **Copy button**.                                      | `expandable`, `nocopy`             |
| **Copy code**           | Copies the code while you edit.                                                                 | None                               |

Inside a code group, the tabs name the blocks, so there is no icon or file name in a block's header. Each tab has its own **Code block settings**.

## Using with Code Editor

When working in a code editor, you write code blocks and code groups with standard fenced code syntax and the `<CodeGroup>` component.

### Single code block

Use [fenced code blocks](https://www.markdownguide.org/extended-syntax/#fenced-code-blocks) with three backticks and a language identifier:

```typescript
const apiCall = async () => {
  const response = await fetch("/api/docs");
  return response.json();
};
```

````markdown
```typescript
const apiCall = async () => {
  const response = await fetch("/api/docs");
  return response.json();
};
```
````

### CodeGroup with multiple languages

Wrap multiple fenced code blocks in a `<CodeGroup>` component to render them as tabs:

````jsx
<CodeGroup tabs="TypeScript,Python,Bash">
```typescript
const response = await fetch("/api/docs", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ title: "Getting Started" })
});
```

```python
import requests

response = requests.post(
  "https://api.example.com/docs",
  json={"title": "Getting Started"}
)
```

```bash
curl -X POST https://api.example.com/docs \
  -H "Content-Type: application/json" \
  -d '{"title": "Getting Started"}'
```
</CodeGroup>
````

Notes:

- Each fenced block inside `<CodeGroup>` must have a language tag (for example, `typescript`, `python`, `bash`).

- `tabs="TypeScript,Python,Bash"` controls the visible tab labels. If you omit `tabs`, the language names are used instead.

- You can combine `<CodeGroup>` with [Tabs](/components/tabs) or [Steps](/components/steps) when you need more complex layouts.

## Advanced options

Use these attributes and patterns to fine-tune how code blocks and groups render. Attributes go after the language, separated by spaces.

### Title and icon

Add `title` to show a file name or a short label in a bar above the code. Add `icon` to draw an [icon](/customize/icons) before it:

```typescript title="src/lib/client.ts" icon="file-code"
export const client = createClient({
  apiKey: process.env.DOCS_API_KEY,
  timeout: 5000,
});
```

````markdown
```typescript title="src/lib/client.ts" icon="file-code"
export const client = createClient({
  apiKey: process.env.DOCS_API_KEY,
  timeout: 5000,
});
```
````

You can also write the file name right after the language, for example `typescript src/lib/client.ts`.

Inside a code group, the title and icon are not shown. The tab label names the block.

### Added and removed lines

Show a change to existing code in one block. End a line with a comment that holds `[!code ++]` for an added line, or `[!code --]` for a removed line:

```javascript title="config.js"
export const config = {
  retries: 3,
  timeout: 5000, // [!code --]
  timeout: 10000, // [!code ++]
};
```

````text
```javascript title="config.js"
export const config = {
  retries: 3,
  timeout: 5000, // [!code --]
  timeout: 10000, // [!code ++]
};
```
````

- The comment is hidden, and the line is tinted and marked with a + or - sign.

- Write the comment in the style of the language: `# [!code ++]` in Python, YAML, or shell, `/* [!code ++] */` in CSS, and `<!-- [!code ++] -->` in HTML.

- `[!code ++:3]` marks that line and the two after it.

- The copy button copies the code after the change. Removed lines and the comments are left out.

- The block needs a language with syntax highlighting. Use `dotenv` instead of `env`, and `bash` instead of `terminal`. In a plain `text` block, the comment shows as written.

In the Web Editor, type the comments into the code. They stay visible while you edit.

### Expandable code blocks

Add `expandable` to collapse a long block. Readers see the first 10 lines and a button, such as **Show all 14 lines**. A block of 10 lines or fewer is always shown in full.

```yaml title=".github/workflows/docs.yml" expandable
name: Check docs
on:
  pull_request:
    paths:
      - "docs/**"
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm run check-docs
```

````markdown
```yaml title=".github/workflows/docs.yml" expandable
name: Check docs
on:
  pull_request:
    paths:
      - "docs/**"
````

### Copy button

Every code block has a copy button. Add `nocopy` to hide it, for example on command output that readers shouldn't run:

```text title="Output" nocopy
Checked 42 pages
0 broken links
```

````markdown
```text title="Output" nocopy
Checked 42 pages
0 broken links
```
````

### Line highlighting

Use the `highlight` prop on a fenced code block to emphasize specific lines:

```javascript highlight="1-2,5"
const greeting = "Hello, World!";
function sayHello() {
  console.log(greeting);
}
sayHello();
```

````markdown
```javascript highlight="1-2,5"
const greeting = "Hello, World!";
function sayHello() {
  console.log(greeting);
}
sayHello();
```
````

### Line focus

Use the `focus` prop to dim non-focused lines and draw attention to a subset of the code:

```javascript focus="2,4-5"
const greeting = "Hello, World!";
function sayHello() {
  console.log(greeting);
}
sayHello();
```

````markdown
```javascript focus="2,4-5"
const greeting = "Hello, World!";
function sayHello() {
  console.log(greeting);
}
sayHello();
```
````

### Line numbers

Add `show-lines="true"` to show line numbers. Combine it with `highlight` or `focus`:

```typescript highlight="1,3" show-lines="true"
interface User {
  name: string;
  age: number;
}
```

````markdown
```typescript highlight="1,3" show-lines="true"
interface User {
  name: string;
  age: number;
}
```
````

### Wrap long lines

Use the `wrap` parameter to control whether long lines stay on a single row with horizontal scrolling or automatically wrap onto the next visual line inside the code block.

You can enable wrapping in several equivalent ways on a fenced block: `wrap`, `wrap="true"`, `wrap=true`.

```typescript wrap="true"
const longLine = "This is a very long line of code that would normally require horizontal scrolling, but with wrap enabled it will wrap to the width of the container instead of overflowing.";
```

```typescript wrap="true"
const longLine = "This is a very long line of code that would normally require horizontal scrolling, but with wrap enabled it will wrap to the width of the container instead of overflowing.";
```

You can also combine `wrap` with other parameters like `highlight` and `show-lines`:

```typescript highlight="1" show-lines="true" wrap="true"
const longLine = "This line is highlighted, shows a line number, and wraps instead of scrolling horizontally across the viewport.";
```

````markdown
```typescript wrap
const longLine = "This is a very long line of code that would normally require horizontal scrolling, but with wrap enabled it will wrap to the width of the container instead of overflowing.";
```

```typescript wrap="true"
const longLine = "This is a very long line of code that would normally require horizontal scrolling, but with wrap enabled it will wrap to the width of the container instead of overflowing.";
```

```typescript highlight="1" show-lines="true" wrap="true"
const longLine = "This line is highlighted, shows a line number, and wraps instead of scrolling horizontally across the viewport.";
```
````

**When to use wrapping:**

- Use `wrap` when you want readers to see the full line without side-scrolling (for example, configuration files or long shell commands), especially in narrow layouts or on mobile devices.

- Avoid `wrap` when alignment and spacing matter (for example, formatted logs, tables, or columns rendered in code), where wrapping can make structure harder to see.

### CodeGroup options

Each code block inside a `<CodeGroup>` takes attributes such as `highlight`, `focus`, `show-lines`, `expandable`, and `nocopy`.

````typescript
<CodeGroup tabs="TypeScript,Python,Bash">
```typescript
const response = await fetch('/api/docs', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ title: 'Getting Started' })
});
```

```python
import requests
response = requests.post('/api/docs',
  json={'title': 'Getting Started'}
)
```

```bash
curl -X POST https://api.example.com/docs \\
  -H "Content-Type: application/json" \\
  -d '{"title": "Getting Started"}'
```
</CodeGroup>
````

<CodeGroup show-lines="true" tabs={["TypeScript","Python","Bash"]}>
  ```tsx TypeScript
  const response = await fetch('/api/docs', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ title: 'Getting Started' })
  });

  ```

  ```python Python
  import requests
  response = requests.post('/api/docs',
    json={'title': 'Getting Started'}
  )

  ```

  ```bash Bash
  curl -X POST https://api.example.com/docs \\
    -H "Content-Type: application/json" \\
    -d '{"title": "Getting Started"}'

  ```
</CodeGroup>

You can also control tabs explicitly:

- `tabs`: Comma-separated list of tab labels, for example `tabs="TypeScript,Python,Bash"`.

- `show-lines`: Set on the component (`show-lines="true"`) to show line numbers for all blocks in the group.

````jsx
<CodeGroup show-lines="true" tabs="Highlighted,Focused">
```javascript highlight="2-3"
const greeting = "Hello, World!";
function sayHello() {
  console.log(greeting);
}
```

```javascript focus="1,3"
const greeting = "Hello, World!";
function sayHello() {
  console.log(greeting);
}
```
</CodeGroup>
````

If you omit `tabs`, language identifiers are used as labels:

````jsx
<CodeGroup>
```typescript
const example = "This tab shows: typescript";
```

```python
example = "This tab shows: python";
```
</CodeGroup>
````

### Attribute reference

Use these attributes on fenced code blocks, including each one in a code group. `tabs` goes on `<CodeGroup>`, and `show-lines` works on both.

<ParamField path="title" param-type="string" required="false" deprecated="false">
  File name or short label shown in a bar above the code. Not shown inside a code group. Example: `"src/lib/client.ts"`.
</ParamField>

<ParamField path="icon" param-type="string" required="false" deprecated="false">
  Icon drawn before the title. Takes any [icon name](/customize/icons). Not shown inside a code group.
</ParamField>

<ParamField path="expandable" param-type="boolean" required="false" deprecated="false">
  Collapses a block longer than 10 lines to its first 10 until the reader expands it. Defaults to `false`.
</ParamField>

<ParamField path="nocopy" param-type="boolean" required="false" deprecated="false">
  Hides the copy button. Defaults to `false`.
</ParamField>

<ParamField path="highlight" param-type="string" required="false" deprecated="false">
  Line numbers or ranges to highlight. Examples: `"1"`, `"1-3"`, `"1,3,5-7"`.
</ParamField>

<ParamField path="focus" param-type="string" required="false" deprecated="false">
  Line numbers or ranges to focus on (blurs other lines). Examples: `"2"`, `"2-4"`, `"1,4-6"`.
</ParamField>

<ParamField path="show-lines" param-type="boolean | string" required="false" deprecated="false">
  Set to `"true"` to show line numbers for a block or an entire group.
</ParamField>

<ParamField path="tabs" param-type="string" required="false" deprecated="false">
  Comma-separated custom tab names (for example, `"TypeScript,Python,Bash"`). Overrides auto-detected language labels.
</ParamField>

<ParamField path="wrap" param-type="boolean | string" required="false" deprecated="false">
  Controls whether long lines wrap inside the code block. Defaults to `false` (no wrapping, horizontal scrolling). Set using `wrap`, `wrap="true"`, or `wrap={true}` to enable `white-space: pre-wrap` and `word-break: break-word` with vertical scrolling only.
</ParamField>
