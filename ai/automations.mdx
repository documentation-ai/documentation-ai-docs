## Automate recurring documentation work with automations

Automations run AI-powered documentation tasks in the background so you can catch issues, sync docs from code, and generate updates without repeating the same manual process.

<Callout kind="note" collapsed="false">
  Automations were previously called **Workflows**. Only the name changed. Your existing workflows are now automations, with the same templates, triggers, schedules, connectors, and run history, and links to the old Workflows pages redirect here. Branches from runs made before the rename keep their `workflow/` prefix; new runs create branches that start with `automation/`.
</Callout>

## What automations are

Automations handle common documentation jobs inside Documentation.AI. You can use them to audit content, enforce standards, generate updates, and run repo-aware tasks that use your connected documentation and code context.

Each automation starts from a template or a custom setup. After you create it, the automation can run on a trigger such as a pull request merge or a schedule, and you can also run it manually when you need an on-demand result.

## Where to find automations

In the dashboard sidebar, under **AI**, click **Automations**. The Automations page is where you create automations, review previous runs, and inspect results.

<Callout kind="info" collapsed="false">
  Automations are currently in beta. Expect the feature set to expand, and review automation output before you merge or publish changes.
</Callout>

## Before you start

Automations depend on your plan and repository connection setup. Confirm these requirements before you try to create one.

<Callout kind="alert" collapsed="false">
  You need all of the following before Automations are available:

  - Any plan, starting with **Starter**

  - A documentation site synced to a **connected Git repository** (GitHub or GitLab)

  - Any repository you want an automation to watch for pull request merges, connected in Documentation.AI

  - Optionally, connect [GitHub](/connectors/github) for code context, plus any of [Jira](/connectors/jira), [Confluence](/connectors/confluence), [Linear](/connectors/linear), [Notion](/connectors/notion), [HubSpot](/connectors/hubspot), [Plain](/connectors/plain), [Intercom](/connectors/intercom), or [User & Agent Feedback](/connectors/user-feedback) for other context the AI agent can read

  - Optionally, enable the **User & Agent Feedback** connector from Agent Settings to use the Self-Heal by User Feedback template
</Callout>

If Documentation.AI can't reach the repository your documentation is published from, the Automations page shows **We cannot reach your repository** instead of the templates. Click **Fix connection** to open your Git settings.

## Built-in automation templates

Start with a built-in template when you want a focused automation for a common task. Choose **Start from scratch** under **Custom** when none of the templates matches your process.

Templates are organized into two categories in the template picker:

- **Self-updating** templates generate or update documentation content based on code changes, repository activity, or user feedback.
- **Auditing** templates check and report on documentation health without modifying content directly.

## Create an automation

Create your first automation from the Automations page in a few steps. The setup flow asks you to choose a template, define how it should run, and pick a trigger repository when needed.

<Steps>
  <Step title="Open the Automations page" icon="home" title-type="p">
    In the dashboard sidebar, under **AI**, click **Automations**.

    If your account and documentation site meet the requirements, you can start a new automation from this page.
  </Step>

  <Step title="Choose a template" icon="plus" title-type="p">
    Select one of the built-in templates, or **Start from scratch** under **Custom**.

    Pick the template that matches the task you want to automate. For example, choose **Broken Link Audit** for content health checks or **Documentation Update from Code** when documentation changes depend on repository activity.
  </Step>

  <Step title="Configure the trigger" icon="play-circle" title-type="p">
    Under **Trigger type**, choose how the automation should start:

    - **On pull request merge** to run after merges in the selected trigger repository

    - **On schedule** to run daily, weekly, or monthly

    You can also start a run yourself at any time with **Run now**.

    After you save the automation, it becomes available in your automations list.
  </Step>

  <Step title="Choose a trigger repository" icon="github" title-type="p">
    If you chose **On pull request merge**, pick the repository to watch under **Trigger repos**. A merged pull request in that repository starts a run. Scheduled automations don't need one.
  </Step>

  <Step title="Select connectors" icon="plug" title-type="p">
    Open **Connectors** in the form. It lists every connector that is on for this documentation project, such as GitHub, Jira, Confluence, Linear, Notion, HubSpot, Plain, Intercom, and User & Agent Feedback. Each one is selected by default. Clear a checkbox to leave that connector out of this automation.

    Keep **GitHub** selected when the automation needs your code. It reads the context repositories you linked in the [GitHub connector](/connectors/github).

    To connect or turn on another connector, click **Manage in Agent Settings**.

    If a template requires a connector that is not yet enabled, the create button prompts you to enable it before proceeding.
  </Step>

  <Step title="Save and verify the automation" icon="check-circle" title-type="p">
    Finish the setup and save the automation.

    A saved automation appears in the automations list. From there, you can wait for its trigger or click **Run now** to confirm the configuration works.
  </Step>
</Steps>

<Callout kind="tip" collapsed="false">
  Click **Run now** after creating the automation to verify the setup before waiting for the next merge or scheduled window.
</Callout>

## Triggers and repository context

Triggers control **when** an automation runs. Connectors control **what context** the automation can read.

### Trigger options

Use the trigger that matches how often the task should happen:

- **On pull request merge** for automations that should react to repository changes

- **On schedule** for recurring checks such as audits or maintenance tasks

To start a run on demand, click **Run now** (the play icon) next to the automation in the automations list, or the play button on its edit page.

If you schedule an automation monthly, pick a day from **1** through **28**. Monthly scheduling does not support days later in the month.

### Trigger repository and code context

The **trigger repository** is the one repository an **On pull request merge** automation watches. A merge in that repository starts a run.

Code context is separate from the trigger. Whenever **GitHub** is selected under **Connectors**, the agent reads code from the context repositories you linked in the [GitHub connector](/connectors/github), the same ones it uses in the editor.

<Callout kind="info" collapsed="false">
  You can only select repositories that are already connected in Documentation.AI.
</Callout>

<Callout kind="info" collapsed="false">
  In addition to repository context, the AI agent can read from [Jira](/connectors/jira), [Confluence](/connectors/confluence), [Linear](/connectors/linear), [Notion](/connectors/notion), [HubSpot](/connectors/hubspot), [Plain](/connectors/plain), [Intercom](/connectors/intercom), and [User & Agent Feedback](/connectors/user-feedback) during automation runs. Connect them in **Agent Settings** and turn them on for your documentation project.
</Callout>

## Review automation runs

Automation runs happen in the background. You can leave the page and return later to check progress or inspect the result.

Run history shows the state of each run as it moves through the automation lifecycle. You may see statuses such as **queued**, **planning**, **executing**, **validating**, **committing**, **completed**, **human needed**, **no action needed**, **failed**, and **cancelled**.

When a run finishes, the result can include:

- A summary of what the automation found or changed

- A **View changes** button, when the run changed files, that opens the run's branch in the editor with its changes shown

- A **Chat with Agent** button, when a Broken Link Audit run has findings, that opens the editor chat pre-loaded with them so you can ask follow-up questions or request fixes

Those outputs help you decide whether to accept the result, investigate further, or continue the task in the editor chat.

## Credit usage

Automations consume AI credits. Credit usage depends on the type of automation and the amount of work required to complete it.

Simple checks usually use fewer credits than repo-aware or multi-step automations. If an automation analyzes multiple repositories or performs more planning and validation, expect higher credit usage.

## Current limitations

The current Automations experience covers the most common user-facing automation paths, but a few constraints affect setup and scheduling today.

<Callout kind="alert" collapsed="false">
  Current limitations include:

  - Automations are in **beta**

  - Automations require a documentation site synced to a **connected Git repository** (GitHub or GitLab)

  - You can only choose a **connected repository** as the trigger repository

  - **Monthly schedules** are limited to days **1** through **28**

  - Not every backend automation capability is exposed in the current UI
</Callout>
