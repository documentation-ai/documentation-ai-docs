Access has two layers. Your **organization role** decides who manages the organization. Your **documentation role** decides what you can do in a documentation project, and you can have a different one on each project: edit one, and only read another.

## Organization roles

| Role       | What they can do |
| ---------- | ---------------- |
| **Owner**  | Admin on every documentation project, including new ones. Manages members, invitations, billing, AI credits, GitHub and GitLab connections and integrations. Can delete the organization. |
| **Member** | Sees only the projects they're added to. Can create a project and becomes its Admin. Sees the members list but can't change it. |

An organization can have several owners, and always has at least one. Every member uses a seat, whatever their roles.

## Documentation roles

Each person has one role on each documentation project they're on.

| What you can do                                                       | Viewer | Commenter | Editor | Admin |
| --------------------------------------------------------------------- | :----: | :-------: | :----: | :---: |
| Read pages, analytics and settings                                    | ✓      | ✓         | ✓      | ✓     |
| Use the AI agent, which acts with your role                           | ✓      | ✓         | ✓      | ✓     |
| Comment, reply and resolve your own threads                           |        | ✓         | ✓      | ✓     |
| Edit pages, navigation and media, and resolve anyone's comments       |        |           | ✓      | ✓     |
| Publish, and work with branches and merges                            |        |           | ✓      | ✓     |
| Manage settings, domains, access control, API keys, connectors and PDF export |   |    |        | ✓     |
| Delete media files and the project                                    |        |           |        | ✓     |
| Add, invite and remove people, and change their roles                 |        |           |        | ✓     |

The [Authoring MCP Server](/ai/authoring-mcp-server) follows the same roles, and every [API key](/api-reference/overview#roles-and-permissions) carries a role of its own.

<Callout kind="info" collapsed="false">
  Editor, Commenter and Viewer come with the Professional plan and above, and AppSumo tier 3 and above. On other plans everyone on a project is Admin. See [Roles and your plan](#roles-and-your-plan).
</Callout>

## Invite people

<Steps>
  <Step title="Open Members" icon="users" title-type="p">
    Go to **Settings > Organization Settings > Members** and click **Invite members**.
  </Step>

  <Step title="Enter their emails" icon="mail" title-type="p">
    Add one or more addresses, separated by commas or new lines.
  </Step>

  <Step title="Choose their roles" icon="user-check" title-type="p">
    Pick **Member** or **Owner**. For a member, tick each project they should get and choose their role on it. An owner becomes Admin on every project.
  </Step>

  <Step title="Send" icon="send" title-type="p">
    Click **Send invitations**. They get an email, and join with those roles when they accept it.
  </Step>
</Steps>

<Image src="https://blob-cdn.documentation.ai/org-53a37986-2c9e-4094-b9e8-1e1ffae9e9ee/doc-b389b141-ae58-4fd5-91f9-6702fae9ac58/1795413379786-gwvliv2f1fu-roles-invite.png?fm=auto&auto=compress%2Cformat" width="2400" height="1516" alt="The Invite members dialog for priya@acme.com as a Member, with Editor on API Reference and Viewer on Acme Docs. Beside it, the invitation she receives, with an Accept invitation button." />

A project's admins can invite people from that project's **Members** page too. Their invitations give access to that project only.

Until someone accepts, their invitation is listed on the **Pending invitations** tab of **Settings > Organization Settings > Members**. Click **Resend** to send the email again, or **Revoke** to cancel it.

## Manage a project's members

Go to **Settings > Documentation Settings > Members** to see everyone on the project you have open. Its admins can:

- **Add members**: give people already in the organization a role on this project. Invite someone new by email from the same dialog.
- **Change a role**: open the role next to a person and pick another.
- **Remove from documentation**: in the same menu. They stay in the organization and keep their roles on other projects.

<Image src="https://blob-cdn.documentation.ai/org-53a37986-2c9e-4094-b9e8-1e1ffae9e9ee/doc-b389b141-ae58-4fd5-91f9-6702fae9ac58/1795413384661-xk9q53wkzck-roles-change-role.png?fm=auto&auto=compress%2Cformat" width="2400" height="1516" alt="A documentation's Members list with the role menu open for Arjun Rao, a Viewer, and the pointer on Editor. The menu lists Admin, Editor, Commenter and Viewer with what each can do." />

Owners are marked **Organization owner**. They're Admin on every project, so their role can't be changed or removed here. To change it, make them a member first.

## Change an organization role or remove someone

Owners manage the organization from **Settings > Organization Settings > Members**. Open the **…** menu next to a person:

- **Make owner**: they become Admin on every project.
- **Make member**: they keep their role on each project.
- **Remove member**: they leave the organization and every project in it.

The last owner can't be made a member or removed. Make someone else an owner first.

## Leave

- **Leave a project**: in **Settings > Documentation Settings > Members**, click **Leave documentation**. You lose access until an admin adds you again.
- **Leave the organization**: in **Settings > Organization Settings > Organization**, click **Leave organization**. The last owner can't leave.

## Roles and your plan

On Starter, Standard and AppSumo below tier 3, everyone on a project is Admin. Editor, Commenter and Viewer still show in every role picker, greyed out with a **Pro** badge. Click **Upgrade** beside one to see the plans that include them.

<Image src="https://blob-cdn.documentation.ai/org-53a37986-2c9e-4094-b9e8-1e1ffae9e9ee/doc-b389b141-ae58-4fd5-91f9-6702fae9ac58/1795413389773-iyxcv5z0nuh-roles-locked-below-pro.png?fm=auto&auto=compress%2Cformat" width="2400" height="1516" alt="On a plan without documentation roles, everyone on the documentation is Admin. In the role menu, Editor, Commenter and Viewer are greyed with a Pro badge, each with its own Upgrade button." />

If you move to a plan without roles, everyone acts as Admin until you upgrade again. The roles you set are kept, and come back when you do.

## Troubleshooting

**Someone can't see a project.** Members only see the projects they're on. An admin of that project, or an owner, adds them from its **Members** page.

**Editor, Commenter and Viewer are greyed out.** Your plan doesn't include documentation roles. See [Roles and your plan](#roles-and-your-plan).

**An invitation didn't arrive.** Ask them to check spam or promotions, then click **Resend** on the **Pending invitations** tab.
